# PPT重建与验收

## 运行时

使用当前环境的演示文稿技能及其支持的API，先获取依赖路径。不要依赖特定用户目录、缓存版本、历史项目脚本或未安装的CLI。需要的运行时不存在时说明具体缺失，不暗中改用整页截图作为最终PPT。

Artifact Tool的创建、导出、最终化与渲染流程以当前文档为准。`scripts/embed_assets.mjs` 只负责素材放置，不能独立识别原图或生成完整PPT；仍需根据原图创建文字、形状、连接和表格。

先使用 `load_workspace_dependencies` 返回的 Python 运行本技能的持久启动脚本：

```text
<runtime-python> <skill>/scripts/run_presentation.py --preflight
<runtime-python> <skill>/scripts/run_presentation.py --cwd <task-build-dir> <absolute-build.mjs>
```

启动脚本从当前 Python 的同级依赖目录定位 Node 和模块，不绑定缓存版本；为构建及其验证子进程设置 `RUNTIME_NODE`、`RUNTIME_NODE_MODULES`、`CODEX_PRIMARY_RUNTIME_NODE_MODULES`、`RUNTIME_PYTHON` 和 `RUNTIME_BIN_DIR`。Windows 下仅在缺失时从系统 API 获取并补齐 `SystemRoot` / `WINDIR`。这些设置只作用于启动进程及其子进程，不修改注册表或全局 PATH。

调用演示文稿技能要求的操作标记、构建脚本和最终校验入口时均通过此启动脚本执行。操作标记仍按演示文稿技能只执行一次，工作目录使用该技能要求的目录。

## 故障重试

- 保存草稿 `candidate.pptx` 后再校验。出现 CSPRNG 初始化失败、缺少运行时环境变量或模块路径错误，先修正启动环境，再只对该草稿重跑失败的校验/最终化步骤。
- 环境错误不触发图像重绘、布局重建或重复运行操作标记。保留已完成素材和通过的检查，限制同一环境问题自动重试两次；仍失败时说明具体错误。
- 内容或布局检查发现实际问题时，只修改相关区域并复核受影响的页面。文件完整性、可编辑对象和最终预览检查保留。

## 坐标与对象

- 记录原图实际尺寸，保持宽高比。可直接用原图像素作为API坐标，或使用一个全局等比例因子。
- 将布局拆成模块，给文本和结构稳定、可辨认的名称。每个图标单独插入，不合并为总图。
- 普通图形关系用原生文本框、预设形状和连接器重建。仅没有合适预设形状的非规则轮廓使用自由路径，不用自由路径模拟常规流程箭头。核对箭头起终点、方向、转折侧和标签归属。
- 按组件创建背景、结构、图标和文字，不粗暴重排所有对象的层级。不要让面板遮住图片或让箭头穿过文字。
- 圆角半径适配对象大小，避免宽面板被默认圆角变成胶囊形。

## 原生形状与流程箭头

- 矩形、圆角矩形、圆、菱形、圆柱等普通结构优先使用PPT对应的预设形状；有现成预设时，不拆成多个自由路径模拟。表格使用原生表格，复杂图标仍使用独立PNG。
- 流程关系使用原生直线、肘形或曲线连接器。用当前演示文稿API的连接器接口，例如 `slide.shapes.connect(sourceShape, targetShape, options)`，显式选择来源和目标的连接边或连接点，优先把端点附着到实际模块形状。移动模块后，连接线应继续附着在模块上。
- 箭头头部必须是连接器自身的端点属性（当前API的 `head`/`tail`），按原图设置形状、宽度、长度及单向或双向。PPT原生三角形箭头端点可以使用；另建一个三角形贴在线末端不可以。禁止用单独的三角形、多边形、PNG或自由路径作为流程箭头头部，组合这些对象也不能代替原生箭头。
- 多次转折的反馈路径采用原生肘形连接器，按当前API支持情况选择转折类型并调整连接点；虚线设置在线条属性中。确需分段时，各段仍为原生线条或连接器，末段使用自带的原生箭头端点，不拼接独立箭头头部。实心宽箭头使用PPT预设块箭头形状。
- 不直接复用旧构建代码中的“线条加三角形”箭头辅助函数。先读当前连接器API文档；若导出后箭头属性丢失，应修复连接器配置或导出步骤并重验，不能以拼接图形作为静默替代。

## 透明边距

PNG需要安全透明留白，但直接把方形PNG塞入目标框可能使图标过小。以素材清单的 `content_box` 计算可见对象比例，不拉伸图标。若库的crop在导出或渲染中没有生效，检查保存后的文件，不能只相信内存属性。

可用辅助函数仅在嵌入时去除透明外边距，素材库PNG保持原样：

```js
import path from 'node:path';
import {pathToFileURL} from 'node:url';
const {createAssetPlacer} = await import(pathToFileURL(path.join(skillDir, 'scripts/embed_assets.mjs')).href);
// sharp来自当前已提供的Node运行时依赖。
const putAsset = await createAssetPlacer({catalogPath, sharp});
await putAsset(slide, 'planner-agent', {left:49, top:191, width:135, height:135});
```

`catalogPath` 指向 `prepare_assets.py` 生成的清单。函数按可见内容等比适配，保留原PNG像素和alpha，设置图片说明。它不会将图片矢量化。

## 文字与可编辑性

重新录入普通文字，保持术语与语义。使用覆盖中文的实际字体，设置对齐、内边距和换行方式。原图一行文字不要无意变成两行，原有多行也不要强挤成一行。

- 重绘前按语义层级建立字号表，例如整图标题、模块标题、正文、辅助标签；同一级尽量使用一个字号，同一组页面的同类文字保持一致，不能因文本长短随意设置不同字号。
- 字号必须为整数pt，优先选择相邻的偶数整数（如16、18、20、22），具体大小依据原图、页面尺寸和可读性确定，不固定套用示例字号。避免18.5、19.2等小数；若使用像素坐标或全局比例映射，应先换算为最终pt再选择整数，不能把API中的整数像素误当成PPT里的整数磅值。
- 长标签先调整文本框宽高、内边距、换行和留白；确需缩小字号时，优先统一调整该层级到合适的偶数整数。不要逐个文本框按宽度连续缩放字号，也不要依赖自动适配在保存或打开时生成隐含的小数字号。确需个别差异时应有清楚的语义或版式理由，仍使用整数并保持同类对象一致。
- 导出后检查实际文字运行及表格文字的字号，并核对继承样式和自动适配设置；同层级出现多个字号时逐一核实原因。必要时检查OOXML中的字号属性，`sz`单位为百分之一磅，整数pt对应可被100整除的值；同时渲染检查溢出和可读性。用户明确指定字号时以用户要求为准。

表格保持原生表格，单元格图标可作为独立PNG叠放。图例符号可以复用PNG，其文字必须可编辑。图标本身是栅格图片，不能将“可移动替换”说成“内部路径完全矢量可编辑”。

## 检查并交付

1. 对照清单核验所有素材和文本，确认角落图标、脚注、状态标记完整。
2. 用当前演示文稿技能的工具检查PPTX包、字体和对象结构，核验实际字号为整数、优先偶数、同层级一致，并排查比例换算和自动适配造成的小数字号。确认原生文本、预设形状、表格及连接器存在，图标为独立图片。检查流程箭头的线条端点属性，不能只以“可编辑对象数量”作为原生箭头合格的依据。必要时查看OOXML中的连接器（p:cxnSp）及线端配置（a:headEnd/a:tailEnd），排除线条末端另有独立三角形的实现。
3. 渲染保存后的最终PPTX并逐页检查溢出、遮挡、对齐、箭头、清晰度，必要时放大局部。检查箭头头部与线条的连接、方向、转折及粗细；在副本中移动一个相连模块，验证已附着连接器仍连接正确，再恢复原位置。没有实际打开PowerPoint时不声称在该软件中检查过。
4. 将PPT、预览、素材ZIP放在用户可访问的输出位置，保留构建源码、清单、原始素材及提示词。

用户只要求一张图转换时交付一页重建图，不附加讲解页、业务改写或新技术模块。后续制作PPT时直接从保留的素材目录筛选，无需重新提取全部图标。
