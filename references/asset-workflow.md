# 图标重绘与清单

## 对象与去重

先做视觉清单，不先猜固定数量。记录对象边界和附属工具，确认极小图标、角落图标、状态标记是否遗漏。文字、普通线条、流程箭头和容器在PPT阶段原生重建，不默认当作PNG。

同一对象多处出现，只生成一次并记录多个原图位置。绿色勾选与红色叉号、拿不同工具的智能体、不同色彩的关系节点分别保留。用户提供的正式标志或必须精确保持的现成素材，优先保留原文件，不任意重绘。

## 单素材提示词模板

按实际对象替换占位内容，不把模板占位符发送给工具：

```text
输入图片为编辑目标。仅分离并高清重绘位于[原图坐标/区域]的[图标名称与外观描述]。
保留原始造型、姿势、颜色、线条风格以及[应保留的工具/附属部件]。
仅输出这个完整对象，真实透明背景；物体内部白色保持不透明。
去掉周围文字、箭头、面板、阴影残片及相邻对象，不添加新的符号或语义。
按工具支持的最高实用原生细节生成，轮廓清楚，细小线条连续。
四周留足透明边距，不能截断天线、把手、工具、火焰或其他伸出部件。
轮廓外没有彩色杂点、白边、黑边或伪棋盘背景。
可见文字不得使用英文逗号或中文顿号或间隔点或破折号或反斜杠作列举和连接，按语义改用“和”“并”“且”或“以及”。
```

单图默认以1024像素级独立素材为实用目标，尊重工具实际支持的分辨率和用户要求。工具没有暴露尺寸参数时只能提出清晰度要求并记录实际结果，不能声称设置了不存在的“最高精度”参数。不要把低分辨率图标插值放大后宣称得到了新增细节。

若用户提供了现成图标总图，可按确认的行列和实际透明分隔切开。先核对实际数量和顺序，不照搬旧项目网格尺寸。没有透明间隔或对象跨格时，局部重新提取；不能盲目均分导致截断。遵循当前图像技能对生成方式的要求。

## 素材清单

生成 `inventory.json`。路径相对于该JSON解析，也可用绝对路径。原图坐标为实际像素，`source_regions` 仅用于定位和复用，整理脚本不会据此生成图标。

```json
{
  "source_images": [
    {"id": "source-1", "path": "../source/framework.png", "width": 1636, "height": 961}
  ],
  "assets": [
    {
      "id": "planner-agent",
      "label": "规划智能体",
      "category": "智能体",
      "input_png": "../assets/raw/planner-generated.png",
      "provenance": "imagegen",
      "prompt_path": "../assets/prompts/planner.txt",
      "source_regions": [{"source_id": "source-1", "bbox": [49, 191, 135, 135]}],
      "notes": "保留手持任务平板"
    },
    {
      "id": "database",
      "label": "数据库",
      "category": "工具",
      "input_png": "../existing-assets/database.png",
      "provenance": "provided",
      "source_regions": [{"source_id": "source-1", "bbox": [908, 377, 30, 32]}]
    }
  ]
}
```

ID使用稳定的英文小写、数字或连字符，仅用于内部映射。`label` 用几个汉字描述图标含义，同时作为最终PNG文件名，例如 `规划智能体.png` 和 `数据库.png`，不要使用英文ID作为成品文件名。不同变体用中文含义区分，例如 `绿色规划智能体` 和 `手持扳手智能体`。`provenance` 为 `imagegen` 或 `provided`，不要把截图裁片标记为生成素材。`imagegen` 项应保存实际使用的提示词文件。

```text
<runtime-python> <skill>/scripts/prepare_assets.py --inventory <inventory.json> --output <task>/assets --canvas-size 1024 --padding 64
```

脚本需要Pillow。它检查真实alpha、保留原始输入副本、在透明画布中居中放置图标，必要时只向下缩放，生成 `png/`、`catalog.json` 和 `index.html`。不放大原始图标、不删除原始内容。不再检查或报告源图前景碰边。原生前景尺寸偏小仍会进入报告，仅结合实际用途判断，不据此自动重绘。整理后的安全透明留白仍由脚本保证。

需要额外素材库副本时，为上述命令添加 `--library-dir <素材库目录>`。未指定时只生成任务输出。指定后，脚本将 `provenance: imagegen` 的最终透明PNG复制到该目录根层级，文件名使用中文 `label`。只复制本次重绘的图标PNG，不复制 `provided` 素材或原始参考图或预览或其他文件，不创建子目录。内容相同的同名文件复用；内容不同则加 `（2）` 等编号保留旧文件。脚本返回的 `library_pngs` 列出实际保存路径；复制失败会报错，不能声称额外保存成功。任务输出目录中的原始素材和清单等照常保留。

## 局部修复与保留

默认在素材目录预览中快速检查实际可见缺陷；仅发现毛边、残字或残缺时放大局部，必要时换背景确认。不要因为前景碰边而额外渲染或重绘。问题只涉及单个图标时，单独调用图像工具修复后更新清单。不要在PPT中用同色矩形遮盖缺陷。

源文件和处理结果均保留。素材ZIP至少包含 `png/`、`catalog.json` 与 `index.html`；最好连同 `raw/` 和 `prompts/` 一起提供，使未来修改可追溯。
